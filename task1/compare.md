# Сравнение технических решений для построение RAG бота для компании QuantumForge Software

Ниже приведены сравнительные обзоры различных частей RAG системы: LLM моделей, энкодеров и векторных баз данных. Сравнение проводится по критериями качества ответов, быстродействия, стоимости владения и проч.

## LLM модели

Исходим из предположения, что в международной компании коммуникация и документация поддерживаются на английском языке.

### DeepSeek 
- Возможно развернуть локально небольшие версии модели (7B, 14B)
- MIT лицензия на open source модели
- Окно контекста в 128000 токенов (1 слово на английском == 0.3 токена)
- Тарификация для платного API: 
  - 1M INPUT TOKENS $0.28
  - 1M OUTPUT TOKENS $0.42
- Стоимость владения при развертывании open source модели: при использовании 4-битных квантованых моделей (7B, 14B) понадобится до 9GB VRAM.
- Качество моделей сопоставимо с аналогичными от OpenAI
- Имеет динамический rate limiting на ключ в зависимости от текущего трафика
- Uptime за последние 90 дней для API составляет 99.95%
- Распределение latency в ms для API может иметь длинный хвост и достигать десятков секунд

### ChatGPT
- Основные модели под проприетарной лицензией, но есть open source gpt-oss (apache лицензия)
- Окно контекста в 400000 токенов (для GPT-5 mini)
- Тарификация для GPT-5 mini:
  - 1M INPUT TOKENS $0.25
  - 1M OUTPUT TOKENS $2.00
- Стоимость владения при развертывании open source gpt-oss-20B: понадобится от 16GB VRAM
- SOTA модели по многим бенчмаркам
- Статический, тир-базированный rate limiting на ключ
- Имеет распределение latency с меньшими выбросами больших значений
- Uptime за последние 90 дней для chat completions api 99.96%

### Итог

В зависимости от доступных мощностей для прототипирования и отладки решения может подойти развернутая open source модель deepseek r1 7B. Для использования внутри компании для улучшения эффективности внутренних бизнес процессов хорошо подойдет модель deepseek r1 за коммерческим API (стоимость генерации ответа ниже). При масштабировании решения до коммерческого продукта стоит рассмотреть переход на OpenAI модели (api deepseek совместимо с api openai, так что переработки на уровне кода приложения не потребуется), так как они обладают лучшими показателями latency и более тонким подбором модели по соотношению качество/скорость под задачу.

## Модели эмбеддингов

Исходим из предположения, что процесс перестроения индекса будет достаточно редким (1 новый документ в два часа) и основную нагрузку будет формировать поток приходящих от пользователей запросов.

### Локальные модели
- Возможные альтернативы
  - sentence-transformers/all-MiniLM-L6-v2: высокая скорость при умеренном качестве, хорошо подойдет для прототипирования
  - BAAI/bge-base-en-v1.5: хорошая скорость и качество, подойдет для внутреннего использования
- Обе модели обладают небольшими требованиями к видеопамяти (в сравнении с llm), стоимость владения не будет сильно большой

### OpenAI Embeddings
- Тарификация для text-embedding-3-small
  - 1M INPUT TOKENS $0.02
- Быстрые и точные модели
- Понятная и прогнозируемая стоимость владения
- SLA на стороне провайдера

### Итог
Для прототипирования и локальной отладки можно использовать sentence-transformers/all-MiniLM-L6-v2 прямо на машине разработчика. Для продакшен решения (и для внутреннего, и с учетом масштабирования) можно сразу взять решение от OpenAI.

## Векторные базы данных

### ChromaDB
- Хорошая для небольших/средних наборов данных; оптимизирована для RAG-приложений.
- Легко встраивается в Python-приложения, часто используется как "in-process" база данных (аналогично SQLite), может работать без отдельного сервера.
- Разработана специально для работы с большими языковыми моделями (LLM) и RAG-системами, имеет простой интерфейс и абстракции.
- Может работать локально или использовать существующую инфраструктуру, не требует выделенных дорогостоящих ресурсов на старте.
- Более простая в использовании, готовая векторная база данных, специально предназначенная для интеграции с современными RAG-приложениями и LLM, с меньшим акцентом на экстремальную производительность по сравнению с FAISS, но с лучшим удобством для разработчика.

### FAISS
- Разработана Facebook AI для максимально быстрого поиска даже в огромных наборах данных (миллионы/миллиарды векторов).
- Это библиотека, а не готовая база данных; требует больше усилий для интеграции в production-среду, управления индексами и масштабирования.
- Предоставляет низкоуровневый контроль над алгоритмами индексации, что требует глубокого понимания векторного поиска для оптимальной настройки.
- Будучи библиотекой с открытым исходным кодом, она бесплатна. Однако для достижения максимальной производительности может потребоваться мощное оборудование, включая GPU, что увеличивает затраты на инфраструктуру.
- Мощная библиотека для высокопроизводительного, низкоуровневого векторного поиска, идеально подходящая для проектов, где скорость и точность на больших масштабах являются критичными.

### Итог
Для прототипирования и отладки лучшим решением на старте может выступать ChromaDB с последующим переходом на FAISS при росте размеров индекса для оптимизации поиска. Возможно и использовании FAISS сразу со старта. Требует дополнительной проработки отказоустойчивого решения для масштабирования решения.

# Конфигурация первичного развертывания RAG бота
Для прототипа решения (MVP стадия) можно использовать конфигурацию:
- DeepSeek R1 API: убираем затраты на поддержку дорогих GPU инстансов, API вызовы со стороны приложения требует минимум ресурсов, а 1М токенов будет более чем достаточно для первичной отладки и запуска - общая тарификация за использование API будет достаточно низкой.
- sentence-transformers/all-MiniLM-L6-v2 развернутый локально: быстрая embedding модель, требующая минимального количество vram и способная показывать хорошую производительность и точность даже на CPU инстансах.
- ChromaDB на одной машине с RAG ботом: для прототипа векторную базу можно держать на одной машине с RAG ботом, исключая паттерны отказоустойчивости и горизонтального масштабирования (необходимо решить это для коммерческого масштабирования).

Конфигурация железа:
Инстанс с 4 vCPU и 8GB. GPU для прототипирования и первичного использования (с небольшим индексом ~30000 векторов) будет излишне (LLM берем от провайдера).
